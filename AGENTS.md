# AGENTS.md

Guidance for AI coding agents working in this repository. Humans should start with [README.md](README.md); this file
condenses what an agent must know before it changes something.

## What this repository is

A Prometheus exporter for the scan results of the Kubescape operator (per-CVE, exposure and configuration posture
series), its Helm chart with an optional `PrometheusRule`, and two Grafana dashboards that read those series.

| Path | What |
|------|------|
| `cmd/kubescape-findings-exporter/` | The exporter: one `package main`, its tests and `testdata/` (real manifests, trimmed) |
| `chart/` | The Helm chart; `chart/files/rules.yaml` holds the recording rules and alerts; `chart/tests/` the unit tests |
| `dashboards/` | Grafana 13 v2 dashboard JSON, generated outside this repository |
| `docs/` | README screenshots |
| `.github/workflows/` | `ci.yml` (tests, release), `lint.yml` (linters on pull requests) |

## Checks

Run what CI runs before you call a change done:

```bash
go vet ./...
go test ./...
helm unittest chart
helm lint chart
```

The pull request linters run in containers (see `.github/workflows/lint.yml` for the exact images and flags):
hadolint on the `Dockerfile`, markdownlint on every `*.md`, jsonlint on every `*.json` and commitlint on the pull
request title and commits.

## Rules

- **English everywhere**: code, comments, docs, commit messages.
- **Conventional commits.** Pull requests are squash-merged and the title becomes the commit on `main`: `fix:` releases
  a patch, `feat:` a minor, `feat!:` or `BREAKING CHANGE:` a major; `chore(deps):` (Renovate) a patch, other chores
  nothing.
- **Leave `version` and `appVersion` in `chart/Chart.yaml` at `0.0.0`.** The release workflow packages the chart
  with the release version; nothing commits to `main` but a merged pull request.
- **No new dependencies** for what the standard library, `client_golang` or `client-go` already do.
- **Comments say why**, not what. Wrap code comments, Markdown and YAML at 120 characters.
- **Keep it small.** No abstractions, options or packages for a need that does not exist yet.

## Metrics

- Every series has the value 1 (count them), except timestamps and `kubescape_posture_control_resources`.
- A new metric or label goes into the metrics table in the README. Mind the cardinality: a label per CVE, package or
  resource multiplies with every cluster.
- The `kubescape_cve_exporter_*` names keep their old prefix on purpose: renaming them breaks existing dashboards and
  alerts.
- A scrape serves the last complete snapshot; a failed refresh keeps the previous one. Keep it that way: never serve a
  half-built series set.

## Chart

- `chart/files/rules.yaml` is **not templated by Helm**, so its Prometheus templates (`{{ $labels.x }}`) stay literal.
  `templates/prometheusrule.yaml` only replaces the placeholders `KUBESCAPE_NAMESPACE` and `GRAFANA_URL` and drops the
  `dashboard_url` annotations without a Grafana URL. Do not add Helm template syntax to that file.
- Every expression keeps the `cluster` label, so one Prometheus can evaluate several clusters.
- A template change gets a test in `chart/tests/default_test.yaml`.

## Dashboards

The JSON in `dashboards/` is generated by a script that lives outside this repository. Do not hand-edit it for
anything beyond a small fix: describe the change in the pull request, and the maintainers carry it over to the
generator. The dashboards depend on the recording rules in `chart/files/rules.yaml`: renaming or removing a recording
rule breaks them.

## Pinned versions

The Kubescape regolibrary release of the frameworks and sections feeds (`v2.0.39` now) is pinned in four places:
`cmd/kubescape-findings-exporter/main.go`, `chart/values.yaml`, `chart/tests/default_test.yaml` and `README.md`.
Renovate bumps them together (`renovate.json`); change them together by hand too.
